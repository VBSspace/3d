# 3D-проекты BVSspace

Просмотрщик мебели для клиентов: модель из Базиса → ссылка, которую клиент открывает на телефоне.

Пример: https://vbsspace.github.io/3d/p15-postirochnaya/

```
viewer/            общий код просмотрщика (Three.js r160 с CDN)
  config.js        адрес сервера замечаний, Telegram, ссылка «Рассчитать»
p15-postirochnaya/ один проект = одна папка (код + изделие, без имени и адреса клиента)
  model.glb        геометрия с текстурами, сжатие Draco
  model.json       детали, двери (ось петель), выдвижные, помещение, цвета фасадов
  index.html       страница проекта
  preview.jpg      картинка для превью ссылки в мессенджерах
tools/             конвертер и скрипты (Python 3, нужны numpy, pillow, DracoPy)
backend/index.py   функция замечаний для Yandex Cloud Functions
```

## Новый проект — одна команда

```
pip install numpy pillow DracoPy
python tools/make_viewer.py "C:\…\шкаф.wrl" --code p16 --title "Шкаф в прихожую" --colors H1145,U702,W1100 --push
```

* `--walls` — `.wrl` стен по замеру. Если не указать, ищется рядом файл «… — стены по замеру.wrl».
* `--colors` — 3–4 варианта цвета фасадов: коды декоров из библиотеки Базиса (`Documents\Bazis\Текстуры`)
  или `Название=#цвет`. Без этого ключа кнопки «Цвет фасадов» нет.
* `--eye 1800,1100` — точка «Как в жизни» (x,z в мм), если автоматически выбрана неудачно.
* `--push` — сразу публикует на GitHub (страница обновится через 1–2 минуты).

Проверить у себя до публикации: `python tools/serve.py` → http://localhost:8000/p16-shkaf-v-prikhozhuyu/
(замечания работают локально, код мастера `#admin=test`).
Превью для мессенджеров: открыть страницу с `?savepreview`, «Ещё» → «Снимок» — сохранится `preview.jpg`,
затем ещё раз запустить make_viewer (или просто закоммитить файл).

### Как конвертер понимает модель

* Имена деталей переводятся из транслита обратно («Bokovina_levaya» → «Боковина левая»).
* Дверь — узел «Дверь…»: ось — по петлям (в какую сторону и вдоль какой кромки они стоят),
  без петель — по названию (левая/правая). Угол открывания 75° (`--door-angle`).
* Выдвижные — узлы «Ящик…», «…выдвижн…», «…откатная…»: едут вперёд на 80 % глубины.
* Отверстия, линии стыка и габаритные рамки отбрасываются; тяжёлая фурнитура и техника упрощаются.
* Стены по замеру — 75 % прозрачности; вход для «Как в жизни» — самый широкий проём в стенах.

## Замечания на модели

Клиент нажимает «Замечание» → место на модели → пишет текст. Метки хранятся на сервере и видны всем,
у кого есть ссылка. Мастер открывает ссылку вида `…/p15-postirochnaya/#admin=СЕКРЕТНЫЙ_КОД` один раз
на своём телефоне/компьютере — после этого там появляются «Ответить», «Решено», «Удалить».
При новом замечании приходит сообщение в Telegram со ссылкой `…/#note=N` прямо на это место.

Сервер — одна функция Yandex Cloud Functions + бакет Object Storage (бесплатный уровень, работает в РФ).
Ключей в коде страницы нет: функция ходит в бакет по IAM-токену своего сервисного аккаунта,
код мастера и токен бота — переменные окружения функции.

Настройка (один раз):
1. https://console.yandex.cloud — войти через Яндекс ID, создать платёжный аккаунт.
2. Object Storage → создать бакет `bvsspace-notes` (доступ: ограниченный).
3. Сервисные аккаунты → `notes-fn` с ролью `storage.editor`.
4. Cloud Functions → `bvs-notes`, среда Python 3.12, точка входа `index.handler`, код — `backend/index.py`,
   сервисный аккаунт `notes-fn`, сделать функцию публичной. Переменные окружения:
   `BUCKET=bvsspace-notes`, `ADMIN_CODE=<придумать>`, `TG_BOT_TOKEN`, `TG_CHAT_ID`,
   `SITE_URL=https://vbsspace.github.io/3d/`, `ALLOWED_ORIGINS=https://vbsspace.github.io`.
5. Telegram: создать бота у @BotFather, нажать у бота «Старт», `python tools/tg_chat_id.py ТОКЕН` → chat_id.
6. Адрес функции (`https://functions.yandexcloud.net/…`) вписать в `viewer/config.js` → `api`, закоммитить.
   Пока `api` пустой, кнопка «Замечание» скрыта.
